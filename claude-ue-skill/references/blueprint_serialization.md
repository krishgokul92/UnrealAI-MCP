# Unreal Engine Blueprint Clipboard Serialization — Skills Reference

> This document defines the complete specification for generating valid Unreal Engine 5 Blueprint clipboard text.
> Text generated following these rules can be pasted directly into the UE5 Blueprint Editor via Ctrl+V.

---

## 1. Format Overview

Blueprint clipboard text uses UE's **T3D (Unreal Text)** serialization format. Each node is wrapped in a `Begin Object` / `End Object` block. Pins are defined as `CustomProperties Pin (...)` entries.

### 1.1 Minimal Node Structure

```
Begin Object Class=/Script/BlueprintGraph.<NodeClass> Name="<UniqueName>"
   <NodeProperties>
   NodePosX=<int>
   NodePosY=<int>
   NodeGuid=<32-char hex GUID>
   CustomProperties Pin (PinId=<32-char hex>,PinName="<name>",...)
   CustomProperties Pin (PinId=<32-char hex>,PinName="<name>",...)
End Object
```

### 1.2 Critical Rules

1. **Every node** must have a unique `Name` within the paste (e.g., `K2Node_CallFunction_0`, `K2Node_CallFunction_1`)
2. **Every NodeGuid** must be a unique 32-character uppercase hex string
3. **Every PinId** must be a unique 32-character uppercase hex string
4. **Connections are bidirectional** — if Pin A links to Pin B, then Pin B must also list Pin A in its `LinkedTo`
5. **Indentation** uses 3 spaces for properties inside `Begin Object`
6. **No trailing newline** after the final `End Object`
7. **Pin properties** are comma-separated with NO spaces between key=value pairs inside the parentheses
8. **Direction** defaults to input (`EGPD_Input`). Output pins must specify `Direction="EGPD_Output"`

---

## 2. GUID Generation

GUIDs are 32-character uppercase hexadecimal strings. They must be unique per paste block.

### 2.1 NodeGuid
- Identifies the node itself
- Example: `AA11BB22CC33DD44EE55FF6677889900`

### 2.2 PinId
- Identifies individual pins on nodes
- Example: `0001000000000000000000000000AA01`

### 2.3 PersistentGuid
- Almost always `00000000000000000000000000000000` for dynamically created pins
- Non-zero only for user-defined custom pins

## 3. Pin Specification

Every pin follows this exact template:

```
CustomProperties Pin (PinId=<32hex>,PinName="<name>",PinFriendlyName=<optional>,Direction=<optional>,PinType.PinCategory="<category>",PinType.PinSubCategory="<sub>",PinType.PinSubCategoryObject=<ref>,PinType.PinSubCategoryMemberReference=(),PinType.PinValueType=(),PinType.ContainerType=<None|Array|Set|Map>,PinType.bIsReference=<bool>,PinType.bIsConst=<bool>,PinType.bIsWeakPointer=False,PinType.bIsUObjectWrapper=False,PinType.bSerializeAsSinglePrecisionFloat=False,LinkedTo=(<optional>),DefaultValue=<optional>,AutogeneratedDefaultValue=<optional>,PersistentGuid=00000000000000000000000000000000,bHidden=<bool>,bNotConnectable=False,bDefaultValueIsReadOnly=False,bDefaultValueIsIgnored=False,bAdvancedView=<bool>,bOrphanedPin=False,)
```

### 3.1 Pin Categories (PinType.PinCategory)

| Category | Description | Example Use |
|----------|-------------|-------------|
| `"exec"` | Execution flow | execute, then, LoopBody |
| `"object"` | UObject reference | Actor, Component, Material |
| `"class"` | UClass reference | ActorClass pin |
| `"bool"` | Boolean | bPrintToScreen |
| `"int"` | Integer | Array Index |
| `"real"` | Floating point (UE5) | Duration (use PinSubCategory="float") |
| `"float"` | Floating point (UE4) | Legacy float pins |
| `"double"` | Double precision | Some UE5 pins |
| `"string"` | FString | InString, display name |
| `"text"` | FText | Localized text |
| `"name"` | FName | Asset names |
| `"struct"` | UStruct reference | LinearColor, Vector, Rotator |
| `"byte"` | uint8 or enum | Enum values |
| `"enum"` | Enum type | Explicit enum pins |
| `"interface"` | UInterface | Interface calls |
| `"delegate"` | Delegate | Event bindings |
| `"softobject"` | TSoftObjectPtr | Soft references |
| `"softclass"` | TSoftClassPtr | Soft class references |
| `"wildcard"` | Any type (resolved at compile) | Array utility functions |

### 3.2 Container Types

| Value | Meaning |
|-------|---------|
| `None` | Single value |
| `Array` | TArray |
| `Set` | TSet |
| `Map` | TMap |

### 3.3 Pin Direction

- **Input** (default): omit `Direction` field entirely, or `Direction="EGPD_Input"`
- **Output**: `Direction="EGPD_Output"`

### 3.4 Pin Visibility

- `bHidden=True` — pin exists but is not shown (e.g., self/Target on static library functions, WorldContextObject)
- `bAdvancedView=True` — pin is hidden behind "Show Advanced" toggle

### 3.5 LinkedTo Syntax

```
LinkedTo=(<TargetNodeName> <TargetPinId>,)
```

Multiple connections:
```
LinkedTo=(<NodeName1> <PinId1>,<NodeName2> <PinId2>,)
```

**CRITICAL**: Always bidirectional. If Pin A → Pin B, then:
- Pin A has `LinkedTo=(<NodeB_Name> <PinB_Id>,)`
- Pin B has `LinkedTo=(<NodeA_Name> <PinA_Id>,)`

## 4. K2Node Types

### 4.1 K2Node_CallFunction
Standard function call node. Used for both impure (with exec) and pure (without exec) functions.

```
Begin Object Class=/Script/BlueprintGraph.K2Node_CallFunction Name="K2Node_CallFunction_<N>"
   FunctionReference=(MemberParent=/Script/CoreUObject.Class'"/Script/<Module>.<OwnerClass>"',MemberName="<FunctionName>")
   NodePosX=<x>
   NodePosY=<y>
   NodeGuid=<32hex>
   CustomProperties Pin (...)
End Object
```

**Impure functions** (BlueprintCallable): Have `execute` input + `then` output exec pins.
**Pure functions** (BlueprintPure): NO exec pins. Only data input/output.

## 7. Node Layout Best Practices

When generating node graphs, follow UE editor conventions:

- **Horizontal spacing**: ~336px between nodes
- **Vertical spacing**: ~180px between parallel branches
- **Flow direction**: Left to right
- **Pure nodes** (no exec): Position below the impure chain they feed into (Y + ~200)
- **Event nodes**: Leftmost position, Y=0

## 9. Validation Checklist

Before finalizing generated Blueprint text:

- [ ] Every `Begin Object` has a matching `End Object`
- [ ] Every `NodeGuid` is unique across the paste
- [ ] Every `PinId` is unique across the paste
- [ ] All `LinkedTo` references are bidirectional
- [ ] `LinkedTo` target node `Name` matches the actual node's `Name` exactly
- [ ] `LinkedTo` target `PinId` matches the actual pin's `PinId` exactly
- [ ] Output pins have `Direction="EGPD_Output"`
- [ ] Input pins do NOT have a `Direction` field (or use `EGPD_Input`)
- [ ] `PinType.PinSubCategoryObject` uses correct object path syntax
- [ ] Struct pins use `ScriptStruct` instead of `Class` in PinSubCategoryObject
- [ ] Array pins have `PinType.ContainerType=Array`
- [ ] Hidden utility pins (self, WorldContextObject) have `bHidden=True`
- [ ] Properties use correct indentation (3 spaces)
- [ ] No duplicated `Name` attributes across `Begin Object` blocks

## 10. Tips for UE Editor Paste

1. **Select All + Copy**: Copy the entire text block from the file
2. **Open Blueprint Editor**: Open any Actor/Level Blueprint Event Graph
3. **Ctrl+V**: Paste directly into the graph canvas
4. **Reconnect Event**: The pasted nodes won't have an entry event — connect the first `execute` pin to BeginPlay or a Custom Event
5. **Compile**: Hit Compile — UE will validate all connections and flag errors
6. **Check Output Log**: Any paste errors will appear in the Output Log

---

## 11. Known Limitations

1. **Variables**: Pasted blueprints cannot reference variables that don't exist in the target Blueprint. Variable references include `MemberGuid` which must match.
2. **Custom Classes**: References to project-specific classes (e.g., `BP_MyActor`) will fail if the class doesn't exist in the target project.
3. **Version Sensitivity**: Pin metadata fields may vary between UE versions (e.g., `bSerializeAsSinglePrecisionFloat` was added in later UE5).
4. **Macro GUIDs**: ForEachLoop and other standard macro GUIDs are engine-specific. The GUIDs in this document are from UE 5.0–5.5 but may differ in future versions.
5. **GUID Conflicts**: If a pasted node's GUID conflicts with an existing node in the graph, UE will regenerate it silently.
